# 論文の下読み（章ごとの矢印要約）

複数論文を扱うと、比較が要らない論文まで精読の深さで読んで時間を失う。
このスキルは「全部読む」を避け、論文を 3 層で短く掴むための手順を定める。

- 層 0: 読む前に、問いと比較軸を 1 回だけ確認する
- 層 1: 記号表。定義が本文に散らばり英語で追いにくい箇所を 1 枚にまとめる
- 層 2: 章ごとの矢印要約。各章の「問題 → 手段 → 結論」を 4〜7 行の流れで書く

出力はすべて Redmine 転記用の textile で、必ず ``` のコードブロックに入れる。
地の文に置くと端末の markdown 描画で `* ` や `** ` が崩れて見える。

## 入力の取り方

- PDF パス: Read ツールで `pages` を指定して読む。10 ページ超は分割する
- arXiv URL: `https://arxiv.org/pdf/<id>` を scratchpad にダウンロードして PDF として読む。abs ページだけでは本文が取れない
- 技術ブログ URL: WebFetch で本文を取る。章立てがなければ見出し単位を章として扱う

読む範囲は次に限る。証明・ablation・関連研究の網羅部分は読まない。

- Abstract、Introduction 末尾の貢献箇条書き、Conclusion
- 定義（Definition）、問題設定、記号の初出箇所
- 各章の冒頭段落と末尾段落、命題・定理の主張文（証明は読まない）
- 実験設定（データの出所・規模）と主結果の表

## 層 0: 問いと比較軸の確認

論文は自分の問いに照らして読むもので、問いがないと論文側の論理に引っ張られて全部読むことになる。
会話や渡されたチケットに問いが書かれていればそれを使い、確認しない。
書かれていなければ、次の 1 問だけ選択式で聞く。自由入力は求めない。

```
この論文を読む目的はどれですか
- a. 概要を掴む（自タスクとの関連・アプローチのヒント）
- b. 正確な比較（前提条件・アプローチの一致を他論文と照合）
- c. 手法の習得（導出の鎖を追う）
- d. その他（直接指定）
```

目的に応じて層 1 と層 2 の深さを変える。概要目的で記号表や小節まで書くと、下読みのはずが 100 行を超えて読まれなくなる。

| 目的 | 記号表 | 章の単位 | 1 章の行数 | 比較軸の表 | 全体の目安 |
| --- | --- | --- | --- | --- | --- |
| a 概要 | 省く（入札式など中核の 3 記号以内なら注意点に書く） | 章のみ。小節はまとめる | 3〜5 行 | 書かない | 40〜60 行 |
| b 比較 | 書く | 章。照合に要る小節だけ分ける | 4〜7 行 | 書く | 80〜120 行 |
| c 習得 | 書く | 導出の章は小節まで | 導出 7 行、他 3〜4 行 | 書かない | 120〜160 行 |

目的 a で 5 行を超えそうな章は、手段の細部（状態の列挙、定理の条件など）を落とし、「何を、なぜ、どう」の 3 点に戻す。細部は目的 b・c で読み直すときに拾えばよい。

目的 b の比較軸の表は、軸名を次の 6 つに固定する。論文に該当がなければ「該当なし」と書き、軸を消したり別名にしたりしない。
軸名が揺れると、あとで複数論文を横に並べたとき列が揃わない。

```
h3. 比較軸

|_. 軸 |_. 論文 |_. 自タスク |
| 目的関数 | | |
| 制約 | | |
| 意思決定単位 | | |
| 観測信号と遅延 | | |
| データ出所と規模 | | |
| 評価指標 | | |
```

自タスク側が会話から分からない欄は「要確認」と書く。

## 層 1: 記号表

節ごとに表を分ける。1 表 7 行を超えるなら節内でさらに分ける。
列は「記号 | 意味」の 2 列が基本で、契約種別や前提の違いで意味が変わる場合だけ 3 列目を足す。
セルは 15 字以内。文章は表の外に書く。

表の直後に「読むときの注意点」を箇条書きで 2〜4 個置く。
同じ記号が別の意味で使われる箇所、星や添字が「最適」を意味しない箇所、教科書と符号規約が違う箇所は、ここに書かないと読者が式で止まる。

```
h3. 1 基本（Def 1〜4）

|_. 記号 |_. 意味 |
| n, i ∈ [n] | キャンペーン数と添字 |
| w_k(b) | 入札 b での落札確率 |

読むときの注意点
* b は入札額、b̂_i は総額で別の量
* θ* の星は最適の意味ではなく乗数の記号
```

数式は KaTeX にせず、x_i や / のような普通の表記で書く。転記後に読めれば十分で、描画の崩れを避ける。

## 層 2: 章ごとの矢印要約

各章を 1 ブロックにする。形式は固定。

```
h3. N 章題の和訳（10〜20 字）

ref. N ORIGINAL SECTION TITLE

出発点となる問題や前提
→ それが困る理由、または直前の章で残った課題
→ 本章で取る手段
→ 手段が成り立つ条件や、導出で使う事実
→ 得られた結論や式
→ 次章へ引き渡す課題（あれば）
```

書き方の基準

- 1 行は 30 字前後、長くても 50 字（全角 1 字、半角 1 字で数える）。50 字を超えたら削らず、矢印で 2 行に分ける。1 行 1 事実で、因果か順序でつなぐ
- 冒頭の 1 行要約も 60 字以内。長くなるなら「何を、どう解く」だけ残し、貢献の列挙は章の要約に回す
- 矢印は「問題 → 困る理由 → 手段 → 条件 → 結論」の順。この順に並べると、読者が「なぜこの手段か」を章ごとに再構成できる
- 1 章 4〜7 行。超える場合は、派生の話題を「MEMO:」で下に出す
- 命題や定理は「Prop N」「Def N」「Eq N」のように番号で引く。読者が原文の該当箇所へ戻れる。番号は原文の該当ページを開いて突き合わせる。1 つ誤引用があると表全体の信頼が落ちる
- 記号は層 1 の表と同じものを使う。表にない記号を使うなら表に足す
- 数値結果は値を書く。「改善した」だけでは比較に使えない
- 著者の主張と、要約者の補足は分ける。補足は「MEMO:」を頭に付ける

層 0 の目的が a のときは、章の下に小節を立てない。小節の内容は親の章の矢印に吸収し、親の章だけで 3〜5 行にする。
目的が b のときは、全章の後に比較軸の表を 1 つ置く。
目的が c のときは、導出の章で「鎖」を切らさない。緩和 → ラグランジュ → KKT → 双対 → 更新則のように、各段を 1 行ずつ矢印で並べる。

## 出力の順序

1. 層 0 の確認（必要な場合のみ。会話に問いがあれば省く）
2. 論文の 1 行要約と、自タスクとの関連度（A: 照合する / B: 保留 / C: 読まない）を 2 行で
3. 層 1 の記号表（目的 a では省く）
4. 層 2 の章ごとの矢印要約
5. 目的が b なら比較軸の表
6. 自タスクとの差や要約者の補足を MEMO として 1〜3 行

2〜5 をまとめて 1 つのコードブロックに入れる。見出しは h3. から始め、h1・h2 は使わない。
丸カッコは全角（）、文字装飾と絵文字は使わない。文末は体言止めか言い切り。

## 例

`references/example-pita2019.md` に、Pita 2019（Optimal bidding: a dual approach）を目的 c で要約した実例を置いている。
層 1 の注意点の書き方、層 2 の 1 行の粒度、導出の章での鎖の残し方はこれに合わせる。
形式に迷ったときだけ読む。

## 仕上げの確認

出力前に次を数える。超えていたら削るのではなく、派生を MEMO か折りたたみに回す。
行数と字数は目視でなく数える。コードブロックの中身を scratchpad のファイルに書き、`python3 -I` の短いスクリプトで「50 字超の行」「各 h3. 配下の矢印行数」「総行数」を出す。

- 1 行 50 字以内、1 章 7 行以内（目的 a は 5 行）、1 表 7 行以内
- 総行数が目的ごとの目安（a: 60 行、b: 120 行、c: 160 行）に収まっている
- MEMO は合計 3 行以内
- 層 1 の記号が層 2 で使われている
- 章番号・原題・Prop / Def / Eq 番号が原文と一致している
- 目的 b なら比較軸の表が 6 軸そのままの名前で並んでいる
- コードブロックに入っている
