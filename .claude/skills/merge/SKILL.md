# merge — 別セッションの結論を取り込む

<!-- 厳密には squash では?という指摘は受け付けていません -->


## 目的

意図的に分散させたセッション(フォーク・並行作業)の成果を、会話ログ全文ではなく「消化済みの結論」だけ現在のセッションに還流させる。

全文を取り込まない理由: ログ全文はこのセッションのコンテキストを汚染し、ユーザーの読解負荷も増やす。要約は**相手セッション側で行わせる**(相手は自分の文脈を全部持っているので要約に最適な立場であり、こちらのコンテキストを消費しない)。

## 引数の解釈

- **SESSION_ID(推奨、特にフォーク相手)**: UUID。**プレフィクスでよい**(一意に定まる長さなら可)。`~/.claude/projects/*/<プレフィクス>*.jsonl` を Glob して完全な ID とプロジェクトを解決する
- **セッション名**(例: `work-0e`): ListAgents の表示名。名前が分かっているなら確認なしで直接送れる最短経路。ただしフォークはタイトルが元セッションと重複して見え、自動生成名とフォークの対応もユーザーには判別しにくいため、フォーク相手には ID 指定を基本とする
  - 複数マッチ → 候補をナンバリングして AskUserQuestion で選んでもらう
  - 注意: ListAgents の表示名・ref とセッション ID の対応表は存在しない(プロセスは transcript を開きっぱなしにしないため lsof でも取れない)。そのため ID 指定時は下記の「自己確認付き依頼」を使う

## 手順

### 1. 対象セッションの特定

ListAgents で稼働中のセッション一覧を取得する。

- 名前指定 → 一致するセッションにそのまま手順 2 へ
- ID 指定 → まず Glob で完全な ID に解決。稼働中のどのセッションかは特定できないので、直近の更新時刻(transcript の mtime)と開始時刻が近い候補を選び、手順 2 の自己確認付きテンプレートを使う
- 候補が見つからない/どれも該当しない → 相手セッションは終了している。`claude --resume <SESSION_ID>` での再開を案内しつつ、フォールバック(後述)を提案する

### 2. 結論の要約を依頼

SendMessage で依頼する。形式と分量を先に固定するのが重要(相手も LLM なので、指定しないと長文が返ってくる)。

行数上限の目安: 基本 30 行。相手セッションが複数トピックを扱っていそうな場合は「1 トピックあたり 15 行、合計 60 行以内」とする。

**名前指定のとき:**

```
このセッションの成果を現在の別セッションに取り込みます(merge)。
以下の形式で返信してください。経緯の全文転記は不要、合計 30 行以内で。

- 結論:
- 根拠(要点のみ):
- 成果物・参照(ファイルパス・URL):
- 未解決・保留:
```

**ID 指定のとき**(確認と依頼を 1 通に畳む — 往復回数は増やさない):

```
別セッションからの依頼です(merge)。
まず確認: あなたのセッション ID は <完全な SESSION_ID> ですか?
- 違う場合: 「ID不一致」とだけ返信し、この依頼は無視してください。
- 一致する場合: 上記と同じ形式・分量で成果を返信してください。
```

「ID不一致」が返ってきたら次の候補に同じテンプレートで送る。

### 3. 返信の受け取りと提示

返信は相手セッションからの受信メッセージとして届く。届いたら:

- `## Merge: <セッション名または ID>` の見出しを付けてユーザーに提示する
- 以後、この内容を現在の会話の文脈として扱う

数分待っても返信がない場合は、相手セッションが承認待ち等でブロックしている可能性をユーザーに伝える(相手のターミナルを見てもらう)。返信を捏造・推測しないこと。

### 4. 取り込み後の深掘り

さらに詳細が必要になったら、相手に全文を送らせるのではなく、返信の「成果物・参照」に挙がったファイルを直接 Read する。追加の質問は再度 SendMessage で相手に聞いてよい(文脈は相手側に保持されている)。

## フォールバック: 相手セッションが終了している場合

会話ログは `~/.claude/projects/<プロジェクトパスのダッシュ区切り>/<SESSION_ID>.jsonl` に残っている(ID プレフィクスは Glob で解決)。ただし巨大になりうるため**直接 Read しない**。サブエージェント(Explore など)に次を依頼する:

```
<JSONL のパス> は Claude Code セッションのトランスクリプトです。
末尾側から読み、最終的な結論・成果物・未解決点を抽出して
「結論 / 根拠(要点) / 成果物・参照 / 未解決・保留」の形式で 30 行以内で報告してください。
```

報告を受けたら手順 3 と同様に提示する。
