# Claude 振り返り(設定棚卸し + 利用振り返り)

引数 `config` で設定棚卸しのみ、`usage` で利用振り返りのみ、省略時は両方を提案する。
各パートともステップごとに報告し、次に進む前に承認を得る。

# Part 1: 設定の棚卸し(config)

## Step 0: 対象の列挙

- `~/.claude/`: CLAUDE.md / settings.json / settings.local.json / agents/ / skills/ / scripts/
- `enabledPlugins` / `extraKnownMarketplaces` が指すプラグインリポジトリ全体
- `~/dotfiles/bin/` の Claude 連携ツール(transcript・sessions レジストリの内部形式に依存するもの)

シンボリックリンクは `readlink` で実体解決してから走査する。

## Step 1: 分類と報告(承認を待つ)

発見を3分類で列挙し、着手順をナンバリング付き選択肢で提案する。

- **A 壊れている**: モデルと無関係に修正すべきもの
- **B モデル/ハーネス進化で見直し**: 旧世代向けの補助輪・古くなった前提
- **C 掃除**: 未参照・重複・一時設定の残骸

## チェックリスト

### A: 壊れている
- ファイル末尾の欠損(「〜してください：」等で不自然に終わる)。git 履歴で原本を確認し、
  初回コミットから欠損なら復元不可 → 既存文体に合わせて執筆する
- agent 本文が空(frontmatter のみ)。description 内の `@パス` 参照は展開されない点に注意
- スキルの引数プレースホルダ: `$ARGUMENTS` / `$1`.. 以外(`$0` 等)は無効
- SKILL.md のない空スキルディレクトリ(ロードされない)
- フロー変更後に frontmatter の description が旧フローのままになっていないか

### B: モデル/ハーネス進化
- `model:` 固定によるレビュー品質の逆転(メインより弱いモデルにレビューさせていないか)。
  原則は指定削除で親継承、コスト重視の機械的バッチのみ明示指定を残す
- 百科事典的な列挙(設計原則の定義・アンチパターン一覧・言語別イディオム)はモデルが既知。
  「役割 + スコープ + 行動指針 + 出力の要点」に圧縮する(目安 1/3)。description の使用例は
  自動委譲のトリガーになるため維持する
- 固定の出力構造の強制は状況に合わない機械的な出力を誘発しうる。要点のみ残す
- permission・承認まわりの前提(issue 参照・回避策)は、claude-code-guide サブエージェントで
  最新仕様と issue の現状を確認してから改訂する(推測で書き換えない)

### C: 掃除
- settings.local.json に残った一時 allow
- 重複キー(例: `voice` と `voiceEnabled`)
- permission パターンの意味の確認: 先頭 `/` は**設定ファイル相対**、`./` が cwd 相対、
  `//` が絶対パス、`:*` と ` *` は等価。意図とのズレを疑う
- どこからも参照されない docs・スクリプト(grep で参照元を確認。削除はユーザー判断、報告のみ)
- CLAUDE.md と各スキルの重複記述は CLAUDE.md を正として集約する。
  ただし**共有プラグインのスキルは自己完結を優先し、重複を残す**

## 実施時の注意

- settings 変更後は `jq empty` で構文検証する
- 判断が必要な発見(全開 permission の要否等)は選択肢を添えてユーザーに委ねる

# Part 2: 利用の振り返り(usage)

## Step 1: 定量集計(jq で直接実施)

`~/.claude/history.jsonl` から以下を集計する(パイプを使わず jq 単体で):

- 期間・月別件数・プロジェクト別件数(用途の比率を見る)
- スラッシュコマンド使用回数(定着したスキル / 使われず消えたコマンド / /mcp 等の摩擦シグナル)
- プロンプト長分布と 20字未満率(操縦発言の多さ)
- セッションあたりプロンプト数(中央値・p90・最大)

## Step 2: 質的分析(サブエージェントに委譲)

`~/.claude/projects/<project>/*.jsonl` から user 発言のみ抽出させ、直近 2〜3 ヶ月・
15〜25 ファイルをサンプリングして以下を分析させる(引用 80 字以内・全体 120 行以内を指定):

1. 手戻り・修正のパターン(「いえ、」等)と原因分類
2. 複数セッションで繰り返している指示(→ CLAUDE.md / スキル化候補)
3. 短い操縦発言の用途(選択・承認・形式再指示)
4. 長大セッションの多トピック混在・fork 重複
5. 質問の仕方の癖(前提の後出し等)+ 最も効率を損ねるパターン Top3

抽出フィルタ: `.type=="user"` かつ content が文字列、`.isSidechain != true`、
`<` / `Caveat:` 開始は除外。ファイルの全文 Read は禁止(jq で抽出)。

## Step 3: スコアと改善アドバイス

- 基準は **質 / 速さ / 判断コスト**(+環境整備)で 10 点満点。根拠を明示する
- お世辞ではなく実績との乖離を指摘する。乖離が小さければ小さいと正直に言う
- 改善案は記号(A1, B2 等)を振り、深掘り指定しやすくする
- 委譲の判定軸を使う: **その理解を後で本人が使うか**(言い直しテスト・読み手テスト)。
  並列化の提案は「任せられる」タスクに限定する(認知負債の観点。redmine #96928)
- 繰り返し指示は CLAUDE.md 既定値化・スキル化を提案。承認摩擦は
  fewer-permission-prompts の実行を提案
- 公式ベストプラクティス(https://code.claude.com/docs/en/best-practices)と突き合わせ、
  未活用の機能・パターンがあれば紹介する

## Step 4: 外部エコシステムの確認

利用シーンに「手動のコピペ・転記・貼り付け」や摩擦シグナル(/mcp 連打、消えたコマンドの
打ち続け等)が残っていれば、それを消せる外部 skill / MCP / plugin を検討する。

- 探索順: 公式リモート MCP(Notion 等)→ 公式 plugin marketplace(`/plugin`)→
  claude.ai コネクタ → コミュニティ製(最後。中身を確認してから)
- 最新のラインナップは claude-code-guide サブエージェントか公式ドキュメントで確認する。
  **実在確認できないものは提案しない**(導入コマンド・URL は出典付きで示す)
- 提案は利用シーンに紐づけ、優先度順に番号を振り、導入手順と注意点
  (書き込み系 permission・社内ポリシー)を添える

## Step 5: 知見の永続化

確定した学び(好み・摩擦パターン・委譲基準)はメモリまたは CLAUDE.md に反映し、
次回の振り返りで前回からの差分を測れるようにする。

# 頻度の目安

メジャーモデル更新時、または数ヶ月ごと。
