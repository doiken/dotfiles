# 翻訳ポリシー (詳細解説版)

このスキルは「全文逐語翻訳」を行わず、「**要約 + キー箇所の忠実翻訳**」というハイブリッド方針を取る。
本文書では、何を要約し何を忠実翻訳するかの判断基準と書き方の例を示す。

## 基本原則

論文は読み手に主張・根拠・実験結果を伝えるために構造化されている。日本語版で再現すべきは
「**主張の構造**」と「**正確であるべきキー情報**」であって、文体や言い回しの細部ではない。

## 忠実翻訳すべき箇所 (faithful translation)

以下は元の表現の精度が重要なため、ほぼ1対1で日本語化する。視覚的に区別するため `<div class="quote">` などで囲む。

### 1. 定義 (Definition)

問題設定や数式の説明。例:

> **教師なしAD**: `X = {x₁,…,xₙ} ∈ ℝⁿˣᵈ` の n サンプル（各 d 次元）が与えられ、ADモデル M を学習して異常スコア `O := M(X) ∈ ℝⁿˣ¹` を出力する。

### 2. 主要な主張 / Key Takeaway / 結論

論文の核となる発見。例:

> 驚くべきことに、ベンチマーク対象の **教師なし手法のうち統計的に他より優れているものは存在しない**。アルゴリズム選定の重要性を示す。

### 3. 図表のキャプション

図表は論文の「実験結果のサマリー」なので忠実に。

> **Figure 4: 57ベンチマークデータセット上の平均AD性能**
> (a) 教師なし手法の平均ランクと平均AUCROC ...

### 4. 数値結果 (Numerical results)

性能指標は数値そのまま保持。例: `AUCROC = 75.56%`, `γₗ = 5%`, `α = 1.1` など。
数値を変形・四捨五入しない。

### 5. Future Direction / 今後の研究方針

著者の主張する研究方向は読み手にとって価値が高いため忠実翻訳。

### 6. Abstract (要旨)

論文全体の縮約版なので、要約せず忠実翻訳。

## 要約してよい箇所 (summary)

以下は構造と要点が伝わればよく、文ごとの逐語翻訳は不要。

### 1. 各段落の本文 (Body paragraphs)

「何を主張し、何が根拠か」が伝わる粒度で日本語の段落を新たに書き起こす。
1段落=1〜3文の日本語に圧縮することが多い。

**例**: 原文が下記のような段落だった場合
> "Although there are already some benchmark and evaluation works for tabular AD [25,38,42,53,166], they generally have the limitations as follows: (i) primary emphasis on unsupervised methods only without including emerging (semi-)supervised AD methods; (ii) limited analysis of the algorithm performance concerning anomaly types..."

要約版:
> 表形式AD向けには既存ベンチマーク（[25,38,42,53,166] など）が複数あるが、以下の制約がある:
> 1. 主に教師なし手法のみを対象としており、(半)教師あり手法を含まない
> 2. 異常タイプ（局所/大域 など）に関するアルゴリズム性能の解析が限定的
> ...

リスト形式に整理しなおすことで読みやすさが増す場合は積極的に使う。

### 2. 関連研究 (Related Work) の各手法説明

「どんな手法か」が伝わればよい。1手法あたり1〜2文に圧縮。

### 3. 実装の詳細 (Implementation details)

ハイパーパラメータや設定は要点を箇条書きで。例:

> DAGMM: 200 epoch、batch 256、early stopping patience 50、Adam lr=1e-4 (epoch 50で減衰)、潜在次元 1、GMM 4成分、λ₁=0.1、λ₂=0.005

### 4. 補足説明 / 余談

正直、読み飛ばしても理解に影響しない箇所は1文要約 or 省略可。

## 翻訳しない箇所

### 1. 参考文献リスト (References)

書誌情報なので翻訳不要。原文画像のみ表示。
画像のみ表示は `<section class="page image-only">` でCSSが自動的に1カラムに切り替わる。

### 2. 著者・所属

アルファベット表記のまま。`<p class="note">` で控えめに表示。

### 3. 数式そのもの

数式は原文表記を保持。インラインなら `<span class="term">` で囲む。
ブロック数式は原文画像で読めるためテキスト化不要。

### 4. 表の中身

数値の羅列を持つ表 (例: 各データセット × 各アルゴリズムのスコア表) は画像のみ + 列構成の説明で十分。
すべての数値を再現する意味はない。

## ページ単位の判定フロー

各ページについて以下を判定:

```
1. このページのテキストは "何を伝える" 内容か?
   ├─ 章タイトル + 段落本文 → テキスト中心ページ → 詳細解説対象
   ├─ ほぼ図のみ → 図中心ページ → キャプション翻訳のみ
   ├─ ほぼ表のみ → 表中心ページ → 列構成説明のみ
   └─ 参考文献 → 画像のみ表示

2. テキスト中心ページの場合、以下を抽出:
   - 章タイトル → 翻訳して h2/h3 で表示
   - 各段落 → 要約 (3-5行) で書き起こし
   - 定義・主張・キャプション・数値・Future Direction → 該当箇所を忠実翻訳
```

## 用語の扱い

### カタカナ化 vs 原語保持

- 日本語に定着している語: カタカナ (例: 「アルゴリズム」「ニューラルネットワーク」)
- 専門用語で訳語が定まらないもの: 原語のまま (例: "Isolation Forest", "AUCROC")
- 略語: 原語のまま、初出時のみ全名併記 (例: 「異常検知 (Anomaly Detection / AD)」)

### 数式・記号

`<span class="term">` でモノスペース表記:
- `<span class="term">γₗ = 5%</span>`
- `<span class="term">X ∈ ℝⁿˣᵈ</span>`

### 引用番号

`[42]`, `[150]` のような参考文献番号は原文のまま残す (左の画像と対応するため)。

## 視覚的階層

HTML出力では以下を守って読みやすさを保つ:

- `<h2>`: 論文の章 (`1 Introduction`, `2 Related Work` など)
- `<h3>`: 節 (`2.1 ...`, `3.3.1 ...` など)
- `<h4>`: 段落見出し (`Motivation`, `Our design` など)
- `<div class="quote">`: 忠実翻訳ブロック
- `<div class="caption">`: 図表キャプション (黄色枠)
- `<div class="future-direction">`: Future Direction (青色枠)
- `<p class="note">`: 著者情報など軽めの注記
- `<span class="term">`: 数式・記号

## 全文逐語翻訳を求められた場合

ユーザーが「逐語的に全文翻訳してほしい」と要望した場合:

1. このスキルは「詳細解説版」のスキルである旨を説明
2. 代替手段を案内:
   - DeepL / DeepL Pro (PDF アップロード対応)
   - Google翻訳 のドキュメント翻訳
   - Adobe Acrobat の翻訳機能
3. その上で「詳細解説版で進める」or「他ツールに任せる」を選んでもらう

詳細解説版の方がほとんどの学習目的に適しているが、ユーザーが要件を理解した上で別ツールを選ぶのは尊重する。
