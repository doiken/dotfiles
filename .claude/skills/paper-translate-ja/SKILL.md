# Paper Translation (英→日 詳細解説版)

英語の学術論文PDFを、勉強会・研究調査・自己学習で使いやすい日本語版に変換するスキル。

## このスキルの基本方針

**「詳細解説版」アプローチ** — 全文逐語翻訳ではなく、各段落の主旨を日本語で書き起こしつつ、以下のキー箇所のみ忠実翻訳する:

- 定義 (Definition / 数式の説明 / 問題設定)
- 主要な主張 (Key claim / Key takeaway / 結論)
- 図表のキャプション
- 数値結果 (AUCROC, 精度などの指標値)
- Future Direction / 今後の研究方針

理由:
1. **理解補助として実用的** — 段落要約のほうが論文の構造を把握しやすい
2. **発表スライドへの転用が容易** — 各章の主旨が掴みやすい
3. **原著作物の全面再生産を避けられる** — 個人学習目的での要約は適切な利用範囲

## 出力形式

左右対比のHTML 1ファイル:
- **左カラム**: 原文ページのPNG画像 (sticky positioning でスクロール追従)
- **右カラム**: 日本語解説 (要約 + 忠実翻訳ブロック + 図表キャプション)

参考文献ページ・図のみのページは画像のみ表示し解説は付けない (書誌情報・絵は翻訳不要)。

## 事前準備 (承認回数の最小化)

このスキルは外部コマンド (`pdftoppm`, `open`) を使う。初回実行時にユーザーが承認フローで都度許可する負担を減らすため、以下を `~/.claude/settings.json` の `permissions.allow` に登録しておくこと:

- `Bash(pdftoppm:*)` — PDF を PNG に変換
- `Bash(mkdir *)` — 出力ディレクトリ作成 (グローバル設定で既定済みのことが多い)
- `Bash(open *)` — 完成 HTML をブラウザで開く

不足している場合、最初の Step 2 や Step 6 で承認プロンプトが出る。`update-config` スキル経由で追加するのが推奨経路。

ファイル操作は **Read / Write / Edit / Glob ツール**を直接使い、Bash 経由の `cat`/`ls`/`grep`/`find` は避けること (承認プロンプトを避けるため)。

## ワークフロー

### Step 1: 意図と範囲の確認

ユーザーから以下を明確化する。1度のメッセージにナンバリングしてまとめて聞き、回答負荷を減らす:

1. **対象範囲**: 本文のみ / 本文+付録 / 全部 (参考文献含む)
2. **出力先ディレクトリ**: 既定提案として `<元PDFと同じディレクトリ>/<論文名>_ja/` または `~/Documents/<論文名>_ja/` を提示
3. **ファイル名**: 既定 `index.html`

ユーザーが「全文逐語翻訳して」と要求した場合は、要約+忠実翻訳の理由を説明し、代替として要約版を提案する。それでも全文逐語翻訳を希望される場合は、DeepL/Google翻訳のようなドキュメント翻訳ツールを案内する (このスキルは要約版を出すスキルである)。

### Step 2: PDF を画像化

承認回数を減らすため、各コマンドは独立して呼び出す (`&&` チェーン・`|` パイプ・`>` リダイレクトは避ける。`cd` も使わずフルパスで指定する)。

```bash
mkdir -p <output_dir>/pages
```

```bash
pdftoppm -png -r 110 <input.pdf> <output_dir>/pages/p
```

`-r 110` (110 dpi) はファイルサイズと解像度のバランスが良い既定値。読みづらいと感じたら `-r 130` まで上げる。

ページ数の確認は **Glob ツール** (`<output_dir>/pages/p-*.png`) を使う。Bash で `ls | wc -l` のようにパイプを使うと承認パターンにマッチしない。

### Step 3: PDF全体を読む

`Read` ツールの `pages` パラメータを使い、5〜10ページずつ読む (一度に20ページが上限)。
全体構造を把握してから翻訳に入ること。特に:

- どこから References が始まるか (画像のみ表示するため)
- 付録 (Appendix / Supplementary Material) の境界
- 図表中心のページ (画像 + キャプション翻訳のみ)
- テキスト中心のページ (詳細解説対象)

### Step 4: HTML を構築

`assets/template.html` をベースに使う (このスキルディレクトリ内)。テンプレートにはCSSと骨格が含まれている。各ページの `<section class="page">` ブロックを生成する。

**ページタイプ別の扱い**:

| ページタイプ | 表示 | 解説量 |
|---|---|---|
| 本文 (テキスト中心) | 左:画像 / 右:解説 | 段落要約 + キー箇所忠実翻訳 |
| 図中心ページ | 左:画像 / 右:キャプション翻訳 | 図のキャプションのみ翻訳 |
| 表中心ページ | 左:画像 / 右:表の構成説明 | 列の意味と読み方を簡潔に |
| 参考文献ページ | 画像のみ (`class="page image-only"`) | なし |
| 付録の図表ページ | 画像のみ + 短いキャプション翻訳を画像下に | キャプションだけ翻訳 |

詳細な書き分けは `references/translation_policy.md` を参照。

### Step 5: ナビゲーション追加

主要セクションへのアンカーリンクをヘッダー下のナビバーに追加する。例:
- Abstract / Introduction
- Related Work
- 提案手法
- 実験結果
- 結論
- 参考文献
- 付録

### Step 6: ブラウザで開く

```bash
open <output_dir>/index.html
```

(他コマンドと連結せず単独で実行する)

ユーザーに成果物のパスと構成を報告する。

## 翻訳の細かい注意点

### 用語

- 専門用語は原則カタカナ化または原語併記。例: 「Isolation Forest (孤立化森)」は無理に訳さず「Isolation Forest」のまま。
- 数式・記号は原文表記を保持。`<span class="term">` でモノスペース表示。
- 引用番号 [N] は原文のまま残す (本文画像と対応するため)。

### 忠実翻訳ブロックの示し方

定義・主要主張・結論は引用ブロックで視覚的に区別:

```html
<div class="quote">
  ...忠実翻訳した文...
</div>
```

図表キャプションは黄色枠の `caption` クラスで:

```html
<div class="caption">
  <span class="caption-label">Figure N: 元タイトル</span>
  ...キャプション内容の翻訳...
</div>
```

Future Direction / 今後の方向性は青色枠の `future-direction` クラスで:

```html
<div class="future-direction">
  <strong>Future Direction X: タイトル</strong> — 内容
</div>
```

### URL・GitHub リンク

論文中の URL は `<a href="...">` でクリック可能にする。GitHub リポジトリのURLは特に重要なので必ずリンク化。

### 数値・表

性能指標 (AUCROC=75.56% など) は数値そのものを保持。`<strong>` で強調すると見やすい。
大きな表 (例: 各データセットの性能比較) は画像のみ + 列構成の説明で十分。

## エッジケース

### スキャン画質が低いPDF

`pdftotext` で抽出できないことがある。その場合:
- `Read` ツールで PDF 直接読みすると Claude Code はビジョン経由で読める
- ページ画像化は可能なので HTML出力は問題ない

### 数式が多い論文

数式は LaTeX ブロックで原文記述するか、画像のキャプチャを参照する形にする (ページ画像で見えるため)。テキストとして再現は困難。

### 1ページに2段組がある場合

これは画像の方で正しいレイアウトが見えるので、翻訳側はリニアに段落を並べれば十分。原文の段組を再現する必要はない。

### 著者・所属の翻訳

著者名・所属はアルファベット表記のまま残す。日本語化しない。

## 完成時の報告

ユーザーには以下を伝える:
1. 成果物のパス (`<output_dir>/index.html`)
2. 構成の概要 (本文ページ範囲 / 参考文献ページ範囲 / 付録ページ範囲)
3. ブラウザで開いた旨
4. 追加で訳出してほしい節があれば指摘してほしい旨
