# 作業再開メモ出力

数日後に同じセッションを再開することを想定し、記憶があいまいでも作業を再開できる引き継ぎメモを生成する。

## 想定読者

- 数日〜数週間後の自分
- コード差分や git log を見れば一部は思い出せるが、判断の経緯やユーザーから受けた口頭の指示は残っていない

→ コードから読み取れない情報を中心に残し、キャッチアップコストを最小化することが価値の源泉。

## 出力テンプレート

````markdown
# 作業再開メモ — {{topic}}

最終更新: {{YYYY-MM-DD}}
作業ディレクトリ: {{cwd}}

## 概要
100 字程度でセッション全体の目的・現在地を要約。

## やったこと

セッション全体の結論を 50 字程度で 1 行

```
├── 大カテゴリ A
│   ├── [x] 個別の作業・決定事項 #チケット番号
│   └── [ ] 次のアクション（再開時に最初にやること）
└── 大カテゴリ B
    ├── [~] 進行中の作業（どこまで完了したかを付記）
    └── [-] 保留した作業（保留の理由を付記）

凡例: [x] 完了 / [~] 進行中 / [-] 保留 / [ ] 未着手
```
````

## Tree の構成ルール

`redmine-summary` のまとめセクションと同じ要領で構成する。

- 冒頭に結論 1 行（50 字程度）
- 階層は最大 2 段: 親 = 大カテゴリ（20 字程度）、子 = 個別の作業（30〜40 字程度）
- 子ノードの先頭にステータス記号を付ける
  - `[x]` 完了 / `[~]` 進行中 / `[-]` 保留 / `[ ]` 未着手
  - `[~]` は「どこまで完了したか」、`[-]` は「保留の理由」を必ず付記
- **次のアクションは独立セクションにせず、`[ ]` として該当カテゴリに混ぜる**
- 関連リンク（チケット・PR・`path:line`）は子ノードの末尾に付ける
- Tree はコードブロック内に書く（罫線の崩れ防止。リンクはクリック不可になるが許容）

## `[ ]`（未着手）の書き方

抽象的な動詞ではなく、具体的なファイル・関数・操作で書く。

**Bad**: 「テストを修正する」
**Good**: 「`tests/test_foo.py:42` の `test_bar` を fixture 形式に置き換え」

## 保存先

引数で出力先が指定されていればそこへ書き込む。指定がなければ標準出力する。

既存の `RESUME.md` がある場合は上書きせず、内容を確認したうえで以下のいずれかをユーザーに提案する:
1. 新しい日時のセクションとして追記
2. 別ファイル名（例: `RESUME-2026-05-01.md`）で保存
3. 上書き

## 出力前のセルフチェック

- 冒頭の結論 1 行があるか
- 階層が 2 段以内に収まっているか
- `[~]` `[-]` に "どこまで" / "なぜ" が入っているか
- `[ ]` が具体的な操作で書かれているか
- 1 行が長すぎないか（子ノード 30〜40 字目安）
