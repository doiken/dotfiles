# User-level instructions

- 日本語で常に応答する
- 簡潔に。冗長な説明・要約・前置きは不要

## 原則

### 回答・成果物の既定
- 相談・質問には結論先出しで回答のみ。指示があるまで実装・修正に着手しない
- 転記用成果物の既定形式: Redmine 向けは textile、Notion・定例/共有会/勉強会向けは markdown
- 資料ドラフトは、読者・分量・体裁・必須/除外要素を最初に1回で確認してから書き始める
- 音声入力の誤変換は文脈で解釈する。判断を左右する固有名詞が曖昧なときだけ確認する

### サブエージェント戦略
- メインのコンテキストウィンドウをクリーンに保つためにサブエージェントを積極的に活用する
- リサーチ・調査・並列分析はサブエージェントに任せる
- 複雑な問題には、サブエージェントを使ってより多くの計算リソースを投入する
- 集中して実行するために、サブエージェント1つにつき1タスクを割り当てる

### 承認回数の最小化
- **`cd` を使わない** — `git -C /path/to/repo` やコマンドのフルパス指定で代替
- **`&&` チェーンを避ける** — 各コマンドを独立して実行（現仕様ではサブコマンド単位に分解して判定されるが、複合コマンド判定の不具合が残るため引き続き分ける）
- **パイプ `|` を避ける** — allow パターンにマッチしなくなる。コマンド自体のオプションで出力を制限する（例: `git log -20` は `| head -20` 不要、`--stat` は `| head -40` 不要）。出力制限オプションがない場合は Read ツールや Grep ツールで代替する
- **リダイレクト `>` `2>&1` を避ける** — 同上（[#13137](https://github.com/anthropics/claude-code/issues/13137): 未修正のまま自動クローズ。バグ残存）
- `gh search` の日付・Stars フィルタは `>` ではなくレンジ形式（`"2026-01-01..2026-12-31"`）を使う
- venv は `source activate` せずフルパス python を使う（例: `/path/.venv/bin/python`）
- **ファイル検索には Glob ツール、内容検索には Grep ツール、ファイル読み取りには Read ツールを使う**こと。Bash で `find`, `grep`, `cat`, `ls` 等を実行しない（承認プロンプトを避けるため）
- `worktrees/` 直下のシンボリックリンクを Glob・Grep・Read の `path` に指定する場合は、事前に `readlink` で実体パスを解決してから使うこと（シンボリックリンクのままだと allow ルールにマッチしない場合がある）
- ステップや順序に分けて進めると明言した際は、次ステップに進める前に必ず承認を得てください

### 質問の効率化
- **自由入力を求めない**: 確認は必ず選択式にする。名前・値など自由記述が要る場合も、末尾に「その他（直接指定）」を選択肢として置き、既定は選択だけで答えられるようにする
- **説明は数字、選択肢はアルファベット**: 1回の応答内で数字とアルファベットの名前空間を分け、「a-1 で」の一語で一意に指せる状態を保つ
  - 説明・章立てには数字（`1.` `2.` `3.`、Markdown 見出しの `## 1.` を含む）を使う
  - 選択肢には必ずアルファベット（`a.` `b.` `c.`）を使い、その配下は `a-1` `a-2` と親記号を継ぐ
  - 質問が複数あっても選択肢記号は応答全体で通しにする（質問ごとに `a.` から振り直さない）
- **並行作業**: 回答内容に依存しない調査や準備を並行して実施しておく

### 外部ツール・ライブラリの仕様
- 根拠は公式ドキュメントと公開インターフェース（`--help`・型定義・公開 API）を優先し、記載のない挙動に依存しない
- 実装（ソース・バンドル）を参照したときは、公式に記載がないため参照した旨と箇所を明記する
